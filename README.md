# PAGE COUNTER

#### Count pages from pdf, docx, pptx, xlsx, odt, odp, ods, doc, ppt and rtf files

## Install

```bash
npm install page-count
```

## Usage

The file type is detected from the content of the buffer, so the extension of
the file name never matters:

```ts
import { readFileSync } from "fs";
import countPages from "page-count";

const pages = await countPages(readFileSync("document.docx"));
```

You can still pass the type explicitly when you already know it:

```ts
const pages = await countPages(buffer, "docx");
```

Or use the counters directly, which is handy when you only support some formats:

```ts
import { DocxCounter, OdtCounter, PdfCounter, PptxCounter, XlsxCounter } from "page-count";

const pagesDocx = await DocxCounter.count(docxBuffer);
const pagesPdf = await PdfCounter.count(pdfBuffer);
const pagesPptx = await PptxCounter.count(pptxBuffer);
const pagesXlsx = await XlsxCounter.count(xlsxBuffer);
const pagesOdt = await OdtCounter.count(odtBuffer);
```

### Detect the type yourself

```ts
import { detectFileType } from "page-count";

const type = await detectFileType(buffer); // "docx", "pdf", "odp", "doc"...
```

### Estimates, when the file has no stored page count

Office documents do not store pages: the page count is a value the editor
writes when it saves the file after paginating it. Documents generated by
libraries often carry no such value at all.

`count` returns what the file itself states (a stored page count, or the hard
page breaks as a lower bound) and rejects when there is nothing to read.
`estimate` never fails on a readable document: it uses the stored value when
there is one and otherwise derives a number, saying which of the two it did:

```ts
import { estimatePages } from "page-count";

const { pages, estimated, method } = await estimatePages(buffer);
// { pages: 4, estimated: true, method: "content" }
```

Methods: `stored` (read from the file, exact), `content` (layout heuristic for
docx, usually within 10-20%), `parts` (slide parts of a pptx), `sheets` (one
page per worksheet, a lower bound for spreadsheets), `breaks` (1 + explicit
page breaks, a lower bound for rtf).

## Supported formats

| Extension | Counter | Where the page count comes from |
|---|---|---|
| `.pdf` | `PdfCounter` | Page tree of the document (exact) |
| `.docx` `.docm` `.dotx` `.dotm` | `DocxCounter` | `docProps/app.xml` and `lastRenderedPageBreak` marks, plus explicit and section breaks |
| `.pptx` `.pptm` `.ppsx` `.potx` `.potm` | `PptxCounter` | `docProps/app.xml`, or the slide parts of the package (exact) |
| `.xlsx` `.xlsm` `.xltx` | `XlsxCounter` | `docProps/app.xml` (printed pages), or the number of worksheets |
| `.odt` `.ott` | `OdtCounter` | `meta:page-count` of `meta.xml` |
| `.odp` `.otp` | `OdpCounter` | `draw:page` slides of `content.xml` (exact) |
| `.ods` `.ots` | `OdsCounter` | Number of sheets (lower bound) |
| `.doc` `.dot` | `DocCounter` | Page count of the summary information stream of the OLE file |
| `.ppt` `.pps` `.pot` | `PptCounter` | Slide count of the document summary information stream |
| `.rtf` | `RtfCounter` | 1 + explicit `\page` breaks (lower bound) |

Formats with no page information at all are rejected with
`FileNotCompatibleError`: `.xls` (the binary Excel format stores no page count)
and anything that is not a document.

## How docx pages are counted

1. `Properties/Pages` from `docProps/app.xml`, when the editor stored it.
2. `w:lastRenderedPageBreak` marks in `word/document.xml` — Word writes one per
   rendered page break when saving, so `marks + 1` is its own pagination.
3. Explicit page breaks (`<w:br w:type="page"/>`) and non continuous section
   breaks, as a lower bound.

The rendered marks already include the explicit breaks, so both signals are
never added together: the largest result wins. `DocxCounter.count` returns that
value and rejects only when the buffer is not a docx at all (not a zip, or
neither `word/document.xml` nor `docProps/app.xml`).

## How reliable is the number?

* **pdf, pptx, odp**: exact, the pages are structural.
* **docx, odt, doc**: exact when the file was last saved by Word or LibreOffice,
  because the editor stores the result of its own pagination.
* **docx generated by a library**: no stored value. `DocxCounter.count` returns a
  lower bound (1 + hard breaks); `DocxCounter.estimate` computes an approximate
  page count from the text volume, the page size, the margins, the font size and
  the number of columns. Expect a 10-20% error: tables, images and floats are
  not measured.
* **xlsx, ods, rtf**: the printed page count depends on the print settings, so
  without a layout engine only a lower bound can be given.

Nothing but rendering gives an exact page count for a document with no stored
pagination, and two layout engines can disagree by a few percent on the same
content. If you need exact numbers for documents you generate, produce them with
an editor that paginates (Word, LibreOffice) and the stored page count will be
there.

## API

```ts
countPages(buffer: Uint8Array | Buffer, type?: FileTypes): Promise<number>
estimatePages(buffer: Uint8Array | Buffer, type?: FileTypes): Promise<EstimateResult>
detectFileType(buffer: Uint8Array | Buffer): Promise<FileTypes>
```

Every counter exposes `count(buffer)` and, when it can do better than a plain
count, `estimate(buffer)`.
